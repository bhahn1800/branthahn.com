Architecture, model & limitations

The telemetry parser validates the event schema and caps input size. A deterministic analysis computes error counts, error fraction, repeated event IDs, and nearest-rank p95 of provided latency samples. Exact event-code matches retrieve authored runbooks. The LLM receives those computed facts and the first matching runbook to draft a read-only investigation question. Generation uses LaMini-Flan-T5-248M, pinned ONNX weights, 8-bit quantization, and Transformers.js 3.8.1 in a Web Worker.

Demo urgency is a simple fixture rule, not a production severity assessment: at least 50% error events means “Elevated”; otherwise any error or p95 at least 1,000 ms means “Review.” Metrics describe only the supplied sample and cannot establish a root cause. Repeated IDs do not prove duplicate side effects. A small LLM can misinterpret evidence, and citation-ID checks do not establish factual accuracy. Unknown event signatures do not receive a generated diagnosis. No agents run tools or commands. Runtime and weights download from jsDelivr and Hugging Face; log content is not sent to a model server.
